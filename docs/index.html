🌍 1. The 5-Node Microservices Fleet

To survive national-level traffic, N.A.K.S.H.A. abandons the monolithic structure. We employ a horizontally scalable, fully decoupled 5-Node architecture. This isolation means a catastrophic traffic spike in Public AI Inference cannot crash the Magistrate's critical systems.

  • Node 1 (Platform): The unified Next.js 14 frontend. Server-Side Rendered (SSR) for SEO and Edge caching.
  • Node 2 (State): PostgreSQL with PostGIS extensions and pgvector. Grafana runs independently on port 3001, providing live National Telemetry via secured anonymous iFrames.
  • Node 3 (AI Gateway): The dedicated intelligence routing engine. Heavy GPU workloads live strictly here.
  • Node 4 (Queue): Distributed Celery workers governed by a Redis broker, enabling asynchronous background execution for thousands of concurrent uploads.
  • Node 5 (Command): A strictly isolated Dev/Admin environment showing live observability (online devs, container health, queue bottlenecks).

🧠 2. Dynamic AI Swapping & The HITL Loop

Relying solely on external APIs (Azure) is a national security risk. We implement Failover Redundancy and an automated Hybrid Continuous Learning Loop.

graph LR Doc[Legacy Deed] --> Router{AI Router Node} Router -->|Primary| VLM[Local Qwen2-VL 7B] Router -->|Failover / Timeout| Azure[Azure GPT-4o] VLM --> PG[(PostgreSQL AIFeedback)] Azure --> PG PG -.->|Immediate| RAG[Dynamic pgvector RAG] RAG -.-> Router PG -->|Batch 1,000 Rows| LoRA[Scheduled LoRA Tuning] LoRA --> VLM

The Mechanics:

  1. Sovereign Execution: The AI Gateway defaults to a locally hosted Vision-Language Model (Qwen2-VL-7B in 8-bit quantization). It processes native Bengali/Hindi Ligatures seamlessly entirely within the VM. Azure OpenAI acts strictly as a load-balancing failover.
  2. Hybrid HITL Learning: Both models share the same PostgreSQL AIFeedback table. When a Magistrate corrects an OCR error in the split-screen UI:
    • Immediate (RAG): The correction embeds into pgvector. The next inference dynamically injects this past mistake as "Few-Shot Context," fixing the AI instantly.
    • Intrinsic (LoRA): Every 1,000 rows, a Celery cron job trains a Low-Rank Adaptation (LoRA) on the local model, fundamentally and permanently teaching it the new dialect without catastrophic forgetting.

🗺️ 4. Autonomous Geospatial Dispute Engine

Disputes in rural land often stem from overlapping physical boundaries. We shift this computational burden entirely to the database layer for zero-latency execution.

graph TD A[Magistrate draws Polygon on React Leaflet] --> B(API calls /save) B --> C{PostgreSQL BEFORE INSERT Trigger} C -->|GiST Bounding Box &&| D{ST_Intersects Math} D -->|No Overlap| E[Commit to Ledger] D -->|Overlap Detected| F[RAISE EXCEPTION] F --> G[Frontend throws DISJOINT ALERT]
The Optimization: GiST + ST_Intersects
Instead of heavy Python geometry processing, a Postgres trigger intercepts the save. It uses the && bounding-box operator against a GiST spatial index. This instantly filters millions of lands to just candidate polygons. Then it runs the exact ST_Intersects() math. If true, it automatically halts the transaction and alerts the Magistrate of a contested boundary.

⚙️ 5. Scaling Celery & Pub/Sub Connectivity

Scaling horizontally introduces massive concurrency risks (race conditions) and client timeout vulnerabilities.

  • Distributed Redlocks: When scaling Node 4, multiple Celery workers fight for the same Redis task. We implement Redis SETNX distributed locks (Redlock algorithm). If Worker A pulls a document, Worker B is mathematically blocked from touching it. Furthermore, we enforce a strict single-instance constraint on celery-beat to prevent duplicated cron jobs.
  • Fixing HTTP Timeouts (Pub/Sub + SSE): Standard load balancers (Nginx) drop connections after 60 seconds, destroying long AI task requests. We replace static HTTP with Server-Sent Events (SSE). FastAPI maintains a 15-second heartbeat ping. When Celery finishes, it publishes a payload to a Redis Pub/Sub channel. FastAPI hears it and instantly streams the JSON directly into the Next.js client. No timeouts, no frozen screens.

🛡️ 6. The Cryptographic Vault (SHA-256 Deduplication)

A digitized record is useless if it can be easily forged. N.A.K.S.H.A. provides absolute mathematical certainty.

hash = SHA-256( registration_number + primary_owners + total_area + geometry )
  • Database Strict Deduplication: Our PostgreSQL schema enforces a UNIQUE(crypto_hash) constraint. If a malicious actor uploads a slightly altered copy of a deed, the database throws an IntegrityError. The Celery worker gracefully rolls back the transaction and permanently flags the upload as a potential forgery.
  • Offline Validation: The system automatically stamps a dynamically generated QR code onto an official ReportLab PDF. Citizens without internet can present physical papers, and any buyer or bank can scan the QR code to instantly verify the deed's mathematical authenticity against our secure portal.

  • SSE (Server-Sent Events): Keeping a lightweight, one-way connection open so the backend can push live updates to the frontend without standard HTTP 60-second timeouts.
  • GiST Indexing: An advanced, rapid search tree used by PostGIS to instantly filter geospatial bounding boxes.

❓ 8. Team Q&A (Internal PPT Reference)

Use these answers to defend the architecture while drafting the presentation or answering judge questions.

  • Q: Why are we deploying a Local AI Model (Qwen2-VL) instead of just using Azure?
    A: Data Sovereignty and Resilience. Government data is highly sensitive. Processing it entirely locally ensures 100% privacy and eliminates API costs. Azure is kept strictly as a failover load-balancer in case the local node crashes.
  • Q: How do we prevent Celery workers from processing the same deed twice?
    A: We use Redis 'Redlocks' (SETNX). When a worker node picks up a document, it mathematically locks it. No other container in the horizontal fleet can touch it.
  • Q: How does the AI actually "learn" from Magistrate corrections?
    A: We use a Hybrid loop. Corrections go into our AIFeedback table. Instantly, pgvector uses it for Few-Shot RAG (fixing the AI immediately for that specific document type). Every 1,000 rows, we run a scheduled LoRA fine-tuning script to permanently teach the base model without catastrophic forgetting.
  • Q: How does DigiLocker integration work? Do we upload PDFs to their servers?
    A: No. We use India Stack's "Push URI" architecture. We store the PDF securely on our own nodes. We send DigiLocker the metadata, and they securely hit our exposed FastAPI /pull endpoint when the citizen wants to view it.
  • Q: How does the system instantly know if drawn lands overlap?
    A: We don't do the math in Python. A PostgreSQL Database Trigger fires before saving, using a GiST Bounding-Box index (&&) combined with ST_Intersects. It intercepts the save in milliseconds.
