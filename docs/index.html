📖 1. The Story (The Pitch)

The Problem: Government land records (Bhu-Naksha, Khatians) are overwhelmingly trapped in fragile, decaying physical archives or unsearchable legacy scans. This causes massive bureaucratic delays, facilitates land fraud, and creates a nightmare for magistrates and citizens trying to verify authentic ownership.

Our Solution: We built a highly secure, AI-powered digitization engine. N.A.K.S.H.A. doesn't just store documents; it uses Advanced AI to instantly extract metadata from legacy TIFF/JPG scans. It leverages cryptographic hashing to prevent tampering, features a Human-in-the-Loop (HITL) fallback for low-confidence scans, and provides a unified Dashboard for Magistrates alongside a public validation portal for citizens.

🎙️ Trainer's Note: The "Why"

When presenting the architecture, emphasize Asynchronous Decoupling. By placing Redis and Celery between the FastAPI backend and Azure AI, we guarantee the Magistrate's frontend UI never freezes, even if they upload a 500-page TIFF file. The API returns a 200 OK instantly, and Celery does the heavy lifting in the background.

🧠 3. Deep Dive: AI Pipeline & Human-in-the-Loop (HITL)

One of the most critical features of N.A.K.S.H.A. is our rigorous data validation pipeline. AI is powerful, but government records require absolute precision. We implemented a 90% baseline confidence threshold.

The Ingestion Sequence

sequenceDiagram actor Officer participant API as FastAPI participant Celery as Celery Worker participant Azure as Azure Document Intelligence participant DB as PostgreSQL Officer->>API: Uploads Legacy Scan (TIFF/PDF) API->>Celery: Offload Base64 Image to Queue API-->>Officer: Returns 200 OK (Task ID) Celery->>Azure: Send Image for OCR Extraction Azure-->>Celery: Returns JSON (Fields & Confidence Scores) alt Confidence >= 90% Celery->>DB: Save Status: VERIFIED else Confidence < 90% Celery->>DB: Save Status: PENDING_HUMAN_REVIEW DB-->>Officer: Trigger Dashboard Alert end Officer->>DB: Manually Override/Approve (HITL)

How it works: If Azure Document Intelligence extracts a Khatian number but flags it with 88% confidence due to a smudged ink stain on the physical document, the system refuses to auto-verify it. Instead, it is routed to the Magistrate Dashboard under "Pending Verification" for a human officer to review (Human-In-The-Loop).

🔐 4. Deep Dive: Zero-Trust Authentication

To prevent unauthorized terminal access, N.A.K.S.H.A. utilizes a strict Zero-Trust session model.

graph LR Login[User Logs In] --> JWT[FastAPI Issues JWT Token] JWT --> Storage[Stored in sessionStorage] Storage --> Tab[User Closes Tab/Browser] Tab --> Shred[Session Cryptographically Shredded] Shred --> Auth[User Must Re-Authenticate]

🎙️ Trainer's Note: LocalStorage vs SessionStorage

If judges ask about security, point out that most apps use localStorage, which keeps users logged in forever. In a government setting, if an officer forgets to log out of a shared computer, it's a massive vulnerability. By strictly using sessionStorage and a window unmount hook, the session is annihilated the millisecond the window is closed.

💬 5. Deep Dive: The Context-Aware AI Copilot

Our Copilot is not just a generic ChatGPT wrapper. It is a highly specialized, context-injected site guide and database expert.

  • Anti-Hallucination Guardrails: When the Postgres database is empty, LLMs naturally try to guess or invent mock data. We engineered a dynamic context injector: if the DB returns 0 records, the system prompt hard-injects a directive strictly forcing the AI to refuse answering and state the DB is empty.
  • Dynamic Site Navigator: The AI knows the exact routing structure of the Next.js application. It generates standard Markdown links (e.g. [Go to Validator](/verify)) which ReactMarkdown parses into functional React Router links, allowing the AI to literally teleport the user across the application.

🚧 6. Hurdles & Engineering Fixes

(Interactive: Click a card to reveal the engineering fix)

🛑 The Next.js Cloud Network Disconnect

The Hurdle: Next.js static builds run in the client's browser, meaning it couldn't resolve our backend Docker container networking (`localhost`), causing logins to silently drop.

The Fix: We dynamically injected our custom Azure DNS at build-time using Docker args, ensuring the browser securely routed API calls across the public internet to our Azure VM.
🤖 AI Hallucination on Empty Databases

The Hurdle: When the database was empty, the AI Copilot would attempt to "guess" record formats, inventing fake data.

The Fix: We engineered a dynamic context-injection system. If the database returns 0 records, the prompt hard-injects an "EMPTY STATE" directive, explicitly forcing the AI to state the lack of records.
⏳ Celery Asynchronous Bottlenecking

The Hurdle: The Celery worker crashed due to missing asynchronous libraries (gevent) and a hardcoded localhost Redis URL, resulting in a 500 API Error.

The Fix: We mapped the Celery broker URL dynamically via environment variables to the Docker Redis container and integrated the gevent execution pool. This allowed true background threading.
👻 Ghost Containers (Docker State Bug)

The Hurdle: Ubuntu's legacy Python-based docker-compose crashed repeatedly (KeyError: ContainerConfig) when updating containers with new images.

The Fix: We automated a clean-slate deployment pipeline (docker rm -f) that wipes container shells but preserves the permanent postgres_data volume. Guaranteed zero data loss with continuous integration.

For Tech Leads

  • Deployment Command: If you need to refresh the codebase on Azure, strictly run: git pull origin main && sudo docker rm -f $(sudo docker ps -aq) && sudo docker-compose up --build -d. This prevents the ContainerConfig bug while perfectly preserving database data.
  • Database Seeding: To reseed or generate new credentials, run: sudo docker exec -it sih_api bash -c "cd /app && PYTHONPATH=/app python scripts/seed_users.py" and use docker cp to extract credentials.md.
  • Cost Ops: Ensure the VM is shut down via the Azure Portal after presentation rehearsals. The DNS routing automatically resolves even if the Public IP changes on boot.
